# Android 1.0 static background image runtime path (2026-10-31)

## Recovered Android behavior
Source: Android 1.0 `ScenarioResourceManager.GetBackgroundTexture(BackgroundResource)` in Cpp2IL decompiled output and matching IL:
- For `ScenarioBGType.Image` with a non-Native source:
  1. Resolve `resource.FullPath`.
  2. Use `_loadedCustomBackgroundTextures` keyed by FullPath.
  3. If a live cached Texture2D exists, return it.
  4. Otherwise `File.ReadAllBytes(FullPath)`, call `DecodeBackgroundImage(bytes, resource.Name)`, cache and return.
- For Native Image:
  1. Call the game's `CorrectPath(resource.Path)`.
  2. Load the resulting key through Addressables.
  3. Retain the loaded Unity object in the manager's Addressables ownership set.
- `DecodeBackgroundImage` constructs `Texture2D(2,2,RGBA32,false)`, sets name and Clamp wrap mode, then calls `ImageConversion.LoadImage(texture, bytes, markNonReadable:true)`. A false return throws InvalidDataException.

The exact IL is generated by Cpp2IL and contains unresolved native helper placeholders in surrounding control flow; the image/custom-vs-native branch and decode calls are also visible in the decompiled method.

## Portable Unity adapter added
`src/AzureArchive.UnityCompat/BackgroundImageRuntimeCache.Unity.cs` now implements the above runtime split:
- Custom Image: safe descriptor FullPath, synchronous file decode, cache by full path, destroy owned custom textures on Dispose.
- Native Image: uses Unity's `Texture` base type (the recovered game method returns Texture), binds the live manager's instance `CorrectPath(string)` method, and can resolve the inherited `Singleton<ScenarioResourceManager>.Instance` property. It performs async Addressables load, deduplicates in-flight requests, retains an AddressableAssetLease, and releases exactly once on Dispose or callback failure.
- Rejects non-Image descriptors; does not route Spine through the static image loader.
- Caller must use Unity main thread. This is an adapter class, not yet injected into the game's `ScenarioResourceManager` or scene presenter.

## Tests
Unity API stubs verify:
- custom FullPath texture is decoded once and reused;
- custom texture ownership is destroyed on cache Dispose;
- native path passes through the supplied CorrectPath function;
- concurrent native requests share one Addressables operation/result;
- native handle stays retained while cache is alive and releases once on Dispose;
- failed native loads release the handle and reach the failure callback.

GitHub Actions [run 41199317839](https://github.com/x676767xxxx/unity-il2cpp-rebuild/actions/runs/41199317839) passed the complete adapter stub build and tests, including game CorrectPath binding, singleton resolution, custom/native cache ownership, concurrent native request sharing, and in-flight release after disposal.
